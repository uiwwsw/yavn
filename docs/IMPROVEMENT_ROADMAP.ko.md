# YAVN 개선 리뷰와 로드맵

## 이번 개선에서 해결한 것

### 엔진 신뢰성

- 자동저장 선택 기록에 챕터 경로를 추가해 서로 다른 챕터의 동일한 `sceneId/actionIndex`가 충돌하지 않도록 수정
- 대사, 확정 선택, 정답 입력을 최대 300개까지 보존하는 스토리 로그 추가
- 기존 저장 데이터의 `chapterPath` 누락을 허용해 하위 호환 유지
- 파서 기본값과 히스토리 복원을 검증하는 Vitest 회귀 테스트 6개 추가
- 현재 챕터의 실제 action 참조만 수집하는 순수 프리로드 계획 모듈과 회귀 테스트 추가(총 7개)
- 시각 에셋 프리로드를 직렬 전체 선언 방식에서 제한 병렬 + 세션 캐시 방식으로 전환
- 선형 다음 챕터 백그라운드 예열, 데이터 절약/2G 동시성 축소 및 예열 생략
- GitHub Actions에서 Node 22, pnpm 10 기준 테스트와 프로덕션 빌드 자동 검증

### 플레이 경험

- HUD에 현재 챕터 진행도 표시
- `CASE FILE`에서 스토리 기록과 수집 단서를 즉시 전환
- 타이틀 이미지에 게임명이 포함된 경우 `startScreen.showTitle: false`로 제목 중복 제거
- 모바일 HUD 터치 영역, 캐릭터 크기, 하단 대화 시트, 선택/입력 컨트롤, CASE FILE 바텀시트, 3열 단서 도감 개선
- 직선 챕터의 중복 `goto`를 제거해 `0 -> 1 -> 2` 진행도와 다음 챕터 예열 시퀀스 유지
- 데스크톱 1280x720, 모바일 390x844에서 시작 화면, 로딩, 플레이 HUD, 케이스 파일, 인벤토리, 선택, 입력 검증

### 성능과 전달력

- Live2D 렌더러를 동적 로딩해 초기 JavaScript를 665.75KB에서 454.36KB로 축소
- 초기 gzip JavaScript를 181.13KB에서 135.47KB로 축소
- Conan 배경 PNG를 AVIF, 투명 캐릭터 PNG를 WebP로 변환해 대표 이미지 24개를 31.98MiB에서 2.14MiB로 축소(약 93.3%)
- 강제 로딩 시간을 600ms + 완료 200ms에서 첫 챕터 240ms/이후 100ms + 완료 80ms로 단축
- 런처에서 소스 코드와 개발 가이드로 바로 이동할 수 있게 연결
- 실제 파일이 삭제된 게임을 manifest와 sitemap에서 제거해 배포 목록 정합성 복구

## 다음 우선순위

### P0: 독립 IP 샘플

현재 대표 샘플은 기존 상업 IP와 캐릭터에 의존합니다. 공개 포트폴리오의 대표 게임은 오리지널 세계관, 캐릭터, 로고, 음원으로 교체하는 것이 최우선입니다. 엔진 기술 데모와 콘텐츠 저작권을 분리해야 프로젝트 자체의 설계 역량이 선명해집니다.

### P1: 엔진 모듈 경계

`engine.ts`는 로더, 저장, 오디오, 연출 실행, 분기 평가 책임을 함께 가집니다. 다음 단계에서는 `runtime`, `persistence`, `media`, `chapter-loader`로 분리하고 각 모듈의 순수 로직 테스트를 늘립니다.

### P1: 완주 E2E

대표 게임의 TRUE/NORMAL/BAD END를 자동 완주하는 브라우저 시나리오를 추가합니다. 저장 후 새로고침, 챕터 이동, 오답 복구, 엔딩 수집까지 검증하면 포트폴리오에서 가장 강한 품질 증거가 됩니다.

### P2: 제작자 도구

런처에 YAML 진단 결과, 참조 그래프, 도달 불가능 scene, 사용하지 않는 asset을 보여주는 authoring report를 추가합니다. 런타임 엔진을 넘어 실제 제작 파이프라인으로 확장되는 지점입니다.

### P2: 포트폴리오 패키지

- 60~90초 플레이 영상
- YAML 한 장이 분기와 연출로 변환되는 아키텍처 그림
- 초기 번들, 테스트 수, 지원 액션 수의 릴리스별 변화
- 오리지널 샘플 게임과 기술 설명을 분리한 배포 URL
